## What this community is for

A place for developers, researchers, and curious builders to turn ideas into **inspectable demos**, share what works, and document what does not. We focus on practical experiments with:

* Typed decisions
* Transparent results
* Reusable interfaces
* Reproducible examples

## Community projects

| Repository | What to explore |
|---|---|
| **typesafe-playground** | Interactive Jev examples, A/B comparisons, document extraction, routing, games, and simulations. |

## Get started

1. **Learn the API.** Read the official TypeSafe quick start for the upstream API and SDK setup.
2. **Choose a project.** Follow its README for local installation, required tools, and any API-key configuration. Setup differs between repositories.
3. **Inspect an experiment.** Start with synthetic input, identify whether the result is mocked or live, and inspect the decisions, uncertainty, and failure cases before adapting the example.

## Contribute

Bug reports, focused examples, documentation improvements, reproducible experiments, and accessibility fixes are welcome.

* **Start in the relevant repository** — read its `README` and `CONTRIBUTING.md` where present, check existing issues, and submit a focused issue or pull request.
* **Explain your work** — describe the problem, what changed, and how you verified it.
* **Respect attribution** — preserve original author credits and check the repository's license before reusing code.

Keep discussions respectful, specific, and useful. Community project questions belong in the relevant repository; **official product, account, billing, and API-support questions belong with TypeSafe AI's official channels.**

---

## Working responsibly

> [!WARNING]
> Community demos are **experiments**, not guarantees of model accuracy or production readiness. A typed result is not proof of correctness or authorization to execute an action.

* Keep policy and authorization checks in application code.
* Distinguish simulated outcomes from live evaluations.
* Document limitations alongside results.

> [!CAUTION]
> **Never publish API keys or sensitive data** in code, issues, screenshots, or example inputs. Review a project's data-handling notes before using a hosted demo or supplying credentials.
